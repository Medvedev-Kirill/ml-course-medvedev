# 📊 Electricity Load Diagrams Dataset — описание

**Источник:** UCI Machine Learning Repository (ElectricityLoadDiagrams20112014), DOI 10.24432/C58C86

## Файлы

- `electricity_hourly.csv` — 26 304 строки, 5 столбцов (почасовой срез)

## Целевая переменная

- **MT_200 (LOAD_KWH)** — потребление электроэнергии клиентом №200, кВт·ч
- Среднее потребление: **~450 кВт·ч/ч**
- Сезонность: суточная (пик вечером) и недельная (будни выше выходных)
- Тип задачи: **Регрессия (многошаговое прогнозирование)**

## Структура признаков

| Категория | Количество | Примеры |
|-----------|------------|---------|
| Исходный ряд | 1 | MT_200 (целевая) |
| Календарные | 4 | hour, dow, month, is_weekend |
| Циклические | 4 | hour_sin, hour_cos, dow_sin, dow_cos |
| Лаги (создаём) | 7 | lag_1, lag_24, lag_168 |
| Скользящие | 4 | rmean_24, rstd_24, rmean_168, rstd_168 |
| Гармоники Фурье | 7 | sin24_1..3, cos24_1..3 (для ARIMAX) |

## Пропуски

- Явных `NaN` нет (0%)
- Возможны нулевые участки (отключения электроэнергии)
- Особенности DST (переход на летнее время): в марте пропущен 1 час, в октябре дублируется 1 час.

## Обработка

1. **Datetime** → `pd.to_datetime()`, установка в качестве индекса
2. **Регулярность** → `.asfreq('h')` для создания непрерывной сетки (пропуски станут явными NaN)
3. **Пропуски** → линейная интерполяция `.interpolate(method='linear')`
4. **Выбросы** → детекция по IQR (3×), оставляем в ряду, но модели делаем устойчивыми (`robust=True` в STL)
5. **Разделение** → хронологическое: Train = все данные кроме последних 168 часов, Test = последняя неделя (168 часов)

## Feature Engineering

- **TotalPages / Длительность** → для GB-модели создаём скользящие статистики (`rmean_24`, `rstd_24`)
- **Cyclical Encoding** → `hour_sin`, `hour_cos`, `dow_sin`, `dow_cos` (чтобы 23:00 и 00:00 были рядом)
- **Lags** → `lag_1`, `lag_24`, `lag_168` (предыдущий час, вчера, неделю назад)
- **Fourier Terms** → синусы и косинусы для ARIMAX (кодируют сезонность без дамми-переменных)

## Ключевые инсайты

- **lag_168** — сильнейший предиктор (потребление неделю назад)
- **lag_24** — второй по важности (суточный цикл)
- **hour_sin / hour_cos** — объясняют пики вечером и минимумы ночью
- **Gradient Boosting** показывает, что для прогноза на неделю достаточно знать профиль прошлой недели и календарь.
